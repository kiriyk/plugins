# Диагностика ИИ-подборок 0.2.0

## Как получить журнал на телевизоре

1. Открыть «Настройки → ИИ-подборки → Диагностика и журнал». Тот же раздел доступен через «Настройки ИИ → Диагностика» внутри подборок.
2. Включить диагностику **до** повторения поиска. По умолчанию она выключена.
3. Повторить проблемный запрос с теми же фильтрами и дождаться результата или ошибки.
4. Вернуться в диагностику. «Показать журнал» открывает записи: вверх/вниз прокручивают текст, кнопка пульта «Назад» закрывает окно.
5. Выбрать «Скопировать журнал» или «Скачать журнал JSON», если устройство поддерживает эти действия. Для разбора нужен файл ai-picks-diagnostics.json или скопированный JSON.
6. После проверки можно выключить диагностику и очистить журнал.

Записи также появляются в штатной консоли Lampa под меткой AIPicks. «Открыть консоль Lampa» доступно из того же меню. Сам JSON плагина содержит только его диагностические события; общий журнал Lampa может включать записи других компонентов.

В браузере журнал можно получить через window.__aipPicksPlugin.diagnostics.exportText(). Это возвращает строку JSON. В Chrome DevTools доступна команда copy(window.__aipPicksPlugin.diagnostics.exportText()).

Если TV не умеет скачивать файл или копировать текст, остаются просмотр журнала на экране и штатная консоль. Обратная отправка отчёта собственному серверу плагина не требуется.

## Что смотреть

| Событие | Значение |
| --- | --- |
| run_start | Номер запуска, явные фильтры формы и действующие лимиты |
| filters | Нормализованные обязательные условия после ответа ИИ |
| tool_start / tool_result | Какой инструмент ИИ вызвал и чем завершилось действие |
| request_start | Фактический хост, endpoint и разрешённые параметры запроса; секреты и текст поиска исключены |
| request_end | Длительность elapsedMs, успешность, число элементов; код ошибки и HTTP-статус, если Lampa его передала |
| request_cancel | Отмена незавершённого запроса |
| candidate_rejected | Составной ID карточки, нарушенное условие и фактические метаданные facts |
| run_done / run_error | Итог, число результатов и использованный бюджет |

runId связывает записи одного поиска; requestId связывает начало и завершение конкретного HTTP-запроса. scope=catalog означает запрос к каталогу, scope=model — ответ ИИ, scope=search — истёк общий срок всего поиска. У последнего scope запрос мог быть отменён раньше собственного сетевого тайм-аута.

Нормализованные фильтры и параметры discovery — разные этапы. ИИ может искать кандидатов по разным жанровым направлениям; перед показом код всё равно проверяет обязательные условия. Для сопоставления используйте filters, параметры request_start и причины candidate_rejected.

Причины отказа: runtime — длительность превышена или неизвестна; year — год не подходит или неизвестен; country — страна не подтверждена; genres / excluded_genres / unknown_genres — жанры; type — формат; already_shown / duplicate — повтор; unknown_key — неизвестный ID; count_limit — достигнуто заданное число карточек.

Например, runtime при facts.runtimeMinutes=138 и filters.maxRuntimeMinutes=120 означает, что фильм правильно исключён. timeout у discover/movie показывает сетевой сбой получения кандидатов, а не нарушение фильтра самим фильмом.

## Хранение

Журнал включается явно, хранит до 200 записей и до 120000 символов экспортируемого JSON. Старые записи удаляются первыми; обычная перезагрузка их сохраняет. Если хранилище недоступно, поиск продолжается, а поле persistence в экспорте показывает memory: текущие записи доступны до перезапуска.

Не записываются API-ключи, Authorization, email, полные URL, тексты поисковых запросов, промпты, ответы модели и тексты объяснений. Поля проходят белый список и при записи, и при чтении сохранённого журнала. Сетевая ошибка не копируется в журнал как произвольный текст.

Диагностика сама не отправляет отчёт на сервер. Кнопки копирования/скачивания работают по действию пользователя; записи AIPicks доступны и штатным средствам консоли Lampa.
